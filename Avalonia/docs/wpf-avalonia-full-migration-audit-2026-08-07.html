1. 目的与分类口径

本文逐项比较原 WPF 项目和当前 Avalonia.* 项目的代码、界面、运行路径与平台行为。文件已经复制或项目能够编译，不自动等于功能已经迁移。每项差异只归入下列一个主分类；如果同时存在多个问题，以最能描述当前阻塞原因的分类为主，并在说明中交叉引用。

  • A：还没迁移的代码。原项目存在，Avalonia 项目没有等价源码、服务、视图或可达功能。
  • B：迁移但还没实现。已建立类型、命令、视图或接口，但主体为空、抛 NotImplementedException、仅提示“未迁移”、使用占位 UI，或关键分支固定失败。
  • C：已迁移但有较大改动。功能存在，但因架构、框架、平台抽象、数据模型或交互方式改变，不能视为直接逐行移植。
  • D：按用户要求暂时拖延。源码或项目注释有明确“本轮延期/暂时禁用”的证据；不能仅凭缺失推测用户意图。
  • E：因移植框架原因无法直接迁移。依赖 WPF、Windows、DirectX、MahApps、Caliburn/Gemini 等 Avalonia 不具备的机制，必须替代、降级或限定平台。E 表示“不能直接照搬”，不表示功能永远不能用其他方案实现。

3. A 类：还没迁移的代码

A-001 EditorScriptExecutor 整模块缺失

  • 原代码：19 个文件，包括脚本文档提供器、AvalonEdit 文档视图、Roslyn 编译/补全上下文、执行结果模型与全局脚本参数。
  • Avalonia 状态：核心、Desktop、Browser 和 CommandLine 中均没有 EditorScriptExecutor 等价模块，也没有可达的脚本编辑、补全和执行入口。
  • 用户功能损失：不能在编辑器内创建/编辑 C# 脚本文档，不能编译执行脚本，也没有原脚本上下文 API。
  • 证据文件组：OngekiFumenEditor/Modules/EditorScriptExecutor/**；Avalonia 源树同名/等价服务搜索为空。
  • 建议：先由产品明确脚本能力是否仍在迁移范围。若保留，应把 Roslyn 编译/补全、脚本上下文 API 和执行取消抽成不依赖 UI 的服务，Desktop 首期接入 Avalonia 兼容代码编辑器，并为脚本 API 做版本化、超时/取消、异常隔离和受信任边界；Browser 只有在明确沙箱模型后再开放。至少覆盖编译诊断、补全、运行结果、取消、重复执行和脚本访问当前文档的集成测试；若不保留，则应正式归入 D 并清理菜单、文档和扩展承诺。

A-002 OgkiFumenListBrowser 整模块缺失

  • 原代码：10 个文件，包含谱面文件夹/集合模型、难度信息、列表浏览视图及打开元信息浏览器的菜单命令。
  • Avalonia 状态：没有同名模块、模型或视图。
  • 用户功能损失：原谱面集合浏览面板和从列表跳转查看谱面元信息的工作流不存在。
  • 证据文件组：OngekiFumenEditor/Modules/OgkiFumenListBrowser/**。
  • 建议：先迁移独立的文件夹扫描、谱面元信息提取和难度模型，再用虚拟化 DataGrid/树列表恢复浏览与打开命令；扫描必须异步、可取消，并处理无权限、损坏谱面、重复文件和大目录。Desktop 使用文件夹选择器，Browser 使用授权目录与 bookmark；增加样例目录扫描、排序/筛选、取消和双击打开元信息浏览器的端到端测试。

A-003 OptionGeneratorTools GUI 整模块缺失

  • 原代码：44 个文件、5 个窗口/对话框，覆盖 ACB、封面、Music XML 生成，枚举数据选择和对应菜单命令。
  • Avalonia 状态：核心 UI 中没有该模块、窗口、设置页和菜单入口。
  • 设置差异：原 Properties/OptionGeneratorToolsSetting.settings 的 LastLoadedGameFolder 没有迁入 Models/Settings/，JSON source context 也没有注册等价设置模型。因此即使 Desktop 命令行保留了部分生成能力，原 GUI 最近游戏目录状态也不会被读取或保存。
  • 相似但不等价部分：Desktop 项目新增 CommandLine/Commands/Acb、Jacket 等服务，说明部分生成算法以命令行架构重写；它们没有恢复原 GUI、对话框、选择器和设置持久化，故本项仍按 GUI 功能缺失记录，命令行重写另归 C 类。
  • 证据文件组：OngekiFumenEditor/Modules/OptionGeneratorTools/**；Avalonia/src/OngekiFumenEditor.Avalonia.Desktop/CommandLine/Commands/**。
  • 建议：不要把生成算法在 GUI 中再实现一遍；把现有 Desktop 命令行 handler 下沉为可注入的 ACB/Jacket/Music XML 核心服务，由 CLI 和 Avalonia Window ViewModel 共用。恢复 LastLoadedGameFolder 时改用平台设置和 StorageProvider bookmark，并让 GUI 提供参数校验、进度、取消、覆盖确认和结果定位。用同一输入 fixture 对 CLI/GUI 输出做字节或语义等价测试。

A-004 原 Kernel/ProgramUpdater 的 GUI 版本检查/下载链缺失

  • 原代码：DefaultProgramUpdater、IProgramUpdater、VersionInfo、ShowNewVersionDialogViewModel 及对应窗口；包含版本查询、菜单通知按钮、下载 ZIP、启动更新器和 GUI 关闭。
  • Avalonia 状态：当前没有等价的共享 IProgramUpdater、版本查询服务或“新版本”对话框。Desktop 只有后来重写的 updater 应用命令（负责覆盖安装），它不提供原 GUI 的 HTTP 检查、下载和提示 UI。
  • 结论：GUI 版本检查/下载属于 A；其删除/后续重新设计的用户决策另记 D-004。不能因为存在 CommandLine/Commands/Updater 就判定原更新功能整体已迁移。
  • 建议：在 D-004 决策撤销前保持 GUI 入口和设置彻底隐藏，不要把覆盖安装命令误暴露成完整更新器。若恢复，应拆成版本查询、包下载、签名/哈希验证、安装调度和 UI 五层，按安装渠道选择自更新或仅跳转发布页；Browser 不执行本地自覆盖。必须测试伪造清单、校验失败、下载中断、回滚、权限不足和跨版本升级。

A-005 主窗口拖入单个文件打开文档的入口缺失

  • WPF 行为：AppBootstrapper.cs:288-289 给主窗口设置 AllowDrop 并订阅 MainWindow_Drop；AppBootstrapper.cs:393-407 读取 DataFormats.FileDrop，当外部文件数恰为一个时调用 DocumentOpenHelper.TryOpenAsDocument(filePath)。
  • Avalonia 状态：没有在 Desktop 主窗口或 TopLevel 上找到接收外部 StorageItems/文件路径的拖放处理器。FumenVisualEditorView.xaml.cs 的 DragEnter/Drop 只把 Gekimini 内部拖放令牌转给编辑器 ViewModel；DocumentOpenHelper.TryOpenAsDocument 当前可达调用点只有快速打开命令和启动参数处理器。
  • 影响：用户不能把一个工程/谱面文件从操作系统文件管理器直接拖到主窗口打开。DataGrid 行重排、工具箱对象拖放等内部拖放不等价于外部文件拖入。
  • 平台边界：Desktop 可以用 Avalonia DragEventArgs/StorageItems 补回；Browser 需要浏览器文件拖入授权和 StorageProvider 语义，因此不能把 Desktop 修复直接推断为 Browser 等价。
  • 建议：在应用 TopLevel 增加只处理外部 StorageItems 的 DragOver/Drop 协调器，验证单项、支持类型和权限后复用 DocumentOpenHelper；通过明确的数据格式排除工具箱与 DataGrid 内部拖放，并显示可接受/拒绝的拖入反馈。Desktop 和 Browser 分别做一个平台适配器，覆盖单文件、多文件、目录、不支持扩展、内部令牌和打开失败测试。

4. B 类：已迁移但还没实现或仅占位

B-001 InterpolateAll 命令为显式未迁移实现

  • Avalonia 代码：InterpolateAllCommandHandler.Run() 只显示 InterpolateAll is not migrated yet.，随后完成任务。
  • WPF 行为：确认后锁定编辑器，调用插值处理；另有带 XGrid 限制的命令处理器，两者都会执行同一个插值算法的不同工厂分支。
  • Avalonia 差集证据：InterpolateAllWithXGridLimitCommandDefinition 仍在 Commands/OgkrImpl/MenuDefinitions.cs 注册菜单，但源码中没有任何 CommandHandlerBase<InterpolateAllWithXGridLimitCommandDefinition> 或等价 ICommandHandler 注册；该菜单项没有可达处理器。普通命令则有处理器但只提示未迁移。
  • 影响：普通菜单项可触发但不会修改谱面；带 XGrid 限制的菜单项还缺少处理器，不能依赖现有基类自动获得行为。
  • 建议：把旧插值算法提取为可测试的纯业务服务，两个命令 handler 只负责确认、参数/XGrid 限制、编辑器锁定和一次性撤销事务；同时补齐受限命令的 DI 注册。覆盖无可插值对象、曲线节点、XGrid 边界、取消、异常解锁、撤销/重做和大谱面性能测试。

B-002 StandardizeFormat 命令为显式未迁移实现

  • Avalonia 代码：StandardizeFormatCommandHandler.Run() 只显示 StandardizeFormat is not migrated yet.。
  • WPF 行为：选择输出路径、执行标准化、序列化写盘，并可打开输出目录。
  • 影响：用户可以触发命令，但不能得到标准化谱面文件。
  • 建议：将标准化变换和序列化封装为共享服务，GUI handler 使用 StorageProvider 选择输出位置并处理覆盖/取消，Desktop 才提供“在文件管理器中显示”。用解析 -> 标准化 -> 序列化 -> 再解析的 golden fixture 验证对象数量、时间/XGrid、引用关系和幂等性，失败时不得留下半写文件。

B-003 CommonColorPicker 是固定 12 色占位实现

  • Avalonia 代码：视图注释明确说明 Xceed StandardColorPicker 不可用，暂用固定色板占位。
  • WPF 行为：使用完整标准颜色选择控件。
  • 影响：任意颜色编辑、精确颜色输入、色相/饱和度等原控件能力缺失；只有 12 个预设色可选。
  • 建议：采用成熟的 Avalonia 颜色选择控件，或实现包含色相/饱和度/亮度、RGB/ARGB 文本输入、透明度、最近颜色和键盘可访问性的复合控件；固定 12 色可保留为快捷 swatch。增加格式解析、非法输入、alpha、取消/确认、颜色 round-trip 和高对比主题测试。

B-004 批量模式的核心交互行为未迁移

  • Avalonia 代码：BatchModeBehavior 已退化为只保存 CurrentSubmode 的普通 ObservableObject；原 WPF Behavior<FumenVisualEditorView> 中的键盘接管、鼠标按下/抬起、批量刷入、删除、过滤选择、撤销动作和附加/拆卸清理均不存在。
  • 注意：文件中的三个 ConvertBack() 抛异常不是主问题；真正的功能缺口是整个行为主体被移除。
  • 影响：批量模式工具栏可存在，但原批量绘制与过滤交互不能按旧方式工作。
  • 建议：把批量模式重建为独立的编辑器交互状态机/协调器，由集中快捷键路由和指针事件调用，而不是把全部逻辑塞回视图 behavior；每次手势形成单个可撤销事务，并明确 pointer capture、模式切换和 detach 清理。按 15 个子模式建立行为矩阵，覆盖普通/Shift、拖动、取消、删除、筛选、撤销和失焦中断。

B-005 新建空项目流程固定失败

  • Avalonia 代码：FumenVisualEditorViewModel.New() 记录“不支持在没有现有项目文件夹时创建工程”并固定返回 false。
  • 当前已实现部分：从文件夹加载 .nyagekiProj、多工程文件选择、最近项目 bookmark 恢复已有完整新路径。
  • 入口侧影响：FumenVisualEditorProvider.CanCreateNew 同时被设为 false，因此 Gekimini 主菜单“新建”不会列出该 provider；Splash 的“新建工程”虽然绕过菜单直接调用 TryNew()，仍因上述固定返回值无提示地留在原窗口。打开已有工程已不再是旧报告所述的整体缺失，但“新建工程”仍没有完成。
  • 建议：基于 Avalonia StorageProvider 实现“选择/创建工程目录 -> 填写工程元数据 -> 写入 .nyagekiProj -> 初始化谱面/音频引用 -> 建立 bookmark 与最近记录”的完整事务；成功前不要仅把 CanCreateNew 改成 true。过渡期应隐藏或禁用 Splash 的新建按钮并明确提示不可用。补充菜单可见性、取消、写入失败清理、同名文件、无 bookmark 平台和成功后打开文档的测试。

B-006 SVG prefab 工程资源被明确暂时禁用

  • Avalonia 代码：SvgImageFilePrefab 的工程资源访问路径抛出 NotSupportedException("SVG prefab project resources are temporarily disabled.")；ProjectResourceSimpleFile 受 ENABLE_SVG_PREFAB_OBJECTS 条件编译控制。

  • 影响：禁用 OPFS、非安全上下文、隐私模式或初始化权限失败的浏览器仍能显示主界面，但没有可持久化的文件日志、跨实例图片缓存或可靠的临时救援；“写入完成”和“路径可打开”的状态可能误导诊断与故障处理。
