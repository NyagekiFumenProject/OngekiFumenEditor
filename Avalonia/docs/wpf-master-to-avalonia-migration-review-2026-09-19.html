WPF master 到 Avalonia 的迁移实现与缺口调查

调查对象：本地 WPF master 与远端 origin/master 的差异，并核对当前 avalonia12 项目。报告性质：只读调查记录。本文档是本次明确要求新建的唯一文件；没有迁移或修改任何源代码。

结论先行： Avalonia 已经实现了主线改动中最重要的核心模型、解析器、编辑器、选择/检查器、谱面列表、音频、DrawCommand/Skia 渲染、自动保存/项目 I/O、布局和主要命令行工具。但当前仍不是 WPF 全功能等价版本；脚本执行与 RuntimeAutomation、领域 MCP、游戏控制器查看器、OptionGeneratorTools GUI、Save As、Desktop GUI 更新闭环，以及若干视觉/平台行为仍未完整迁移。
证据口径： 本报告的“已迁移”表示当前 Avalonia 源码中存在对应实现或明确的新架构替代；不把同名文件、成功编译或旧报告中的结论单独当作功能等价证明。源码核对使用当前工作树；未在本次文档任务中运行构建、测试或 GUI 冒烟。

1. 调查范围、基线与方法

比较范围是 Git 的 master..origin/master，不是 Avalonia 分支之间的提交差异。原因是用户要求检查“从本地 master 到远端 master 的这些改动”分别有多少已经迁移到 Avalonia。WPF 主线的文件、提交主题和当前 Avalonia 源码分别核对；对于路径消失但存在替代实现的情况，按行为和调用链判断，不按文件复制数量机械判定。

2. 判定分类与证据规则

分类本报告含义判定方式
已迁移Avalonia 有对应领域实现或可追溯的新架构替代。必须能在当前 Avalonia 源码中找到类型、服务、ViewModel、命令或渲染链路证据。
部分迁移已有入口或核心能力，但行为、算法、UI 表现、平台范围或验证证据不完整。明确列出已覆盖和仍不同的部分，不能把部分实现写成完全等价。
未迁移WPF 主线存在可达功能，而当前 Avalonia 没有对应模块、服务或入口。结合 WPF 变更路径和 Avalonia 缺失目录/符号核对。
有意替代WPF 专用实现没有逐行迁移，但被 Avalonia/Gekimini/Skia/CLI 的不同架构取代。记录替代链和行为边界；不能说成“完全没有对应功能”。

报告还区分“源码存在”和“已验收”。本次只读调查没有重新运行全量测试或应用启动；因此即使某项有完整源码，也只称为“源码已迁移”，不把它升级成“运行时完全验收”。

5. 部分迁移：已有入口但尚未达到 WPF 等价

这些领域不能简单标为“没有迁移”，因为 Avalonia 已有可工作的入口或替代实现；同时也不能标为“已完成”，因为算法、UI、平台能力或证据仍有明确差距。

5.1 PlayableArea / DrawPlayableAreaHelper 几何算法

状态：入口和渲染链已迁移，几何实现不是 WPF 的逐项等价实现

  • WPF 主线的实现以 textFieldRangeParam、AdjustLaneIntersection 和 EarcutNet 三角化路径为中心。
  • 当前 Avalonia 的 DrawPlayableAreaHelper 采用可见 TGrid/墙边界采样、lane 边界集合和多边形绘制的另一条路径，并在 frame 内缓存边界。
  • 因此 Avalonia 已经能进入 PlayableArea 绘制，但边界采样密度、墙交点、凹多边形分割、极端 lane/soflan 场景不能仅凭同名 helper 认定相等。
  • 当前分支已有专门的 contract/child-range 测试和 benchmark 提交，但本报告没有重新运行它们；应把“算法不同”作为后续视觉/几何验收边界。

证据：Modules/FumenVisualEditor/Graphics/Drawing/TargetImpl/PlayArea/**（或同目录下的 DrawPlayableAreaHelper 实现）、e88bca1fc（playfield contract）、596448eac（DrawPlayField 行为接管）、DrawPlayableAreaHelperNewP1Benchmarks.cs。这里的结论是“新架构实现并存”，不是 WPF 算法缺失。

5.2 Preview SVG 生成

状态：已迁移可用生成器；完整视觉/资源等价尚未证明

  • Avalonia 有 IPreviewSvgGenerator、DefaultPreviewSvgGenerator、GenerateSvgCommandHandler 和资源图片，能够生成 SVG，并由 Desktop CLI 进一步栅格化 PNG。
  • WPF 主线的 PreviewSvgGenerator 目录有 9 个变更文件，旧生成器包含更长的对象、资源、Soflan 和注释处理路径；当前 Avalonia 实现明显是重新组织的较小实现。
  • 尚未据此证明所有对象类型、主题颜色、字体、外部资源、Soflan weighted 模式和 PNG 栅格结果与 WPF 像素等价。

证据路径：Modules/PreviewSvgGenerator/、OngekiFumenEditor.Avalonia.Desktop/CommandLine/Commands/Svg/、DefaultPreviewSvgGenerator.LegacyCommented.cs。这属于“功能入口迁移 + 视觉验收缺口”。

5.4 ProgramUpdater：CLI 已迁移，Desktop GUI 更新闭环不完整

  • 此前审查中已经用探针验证过独立 updater 的若干进程契约，但这证明的是 updater 服务/命令行，不等同于真实编辑器从 GUI 发起升级的端到端闭环。

状态：用户可达 GUI 闭环未证实，CLI/服务部分已迁移

  • Avalonia 有更新服务和 updater CLI，但当前模块清单没有对应的完整更新对话框/设置入口。
  • 如果产品只要求由外部发布脚本调用 updater CLI，则 CLI 部分可算已迁移；若要求从编辑器菜单检查并安装更新，则仍是未迁移。

7. 有意不直接搬运的 WPF 实现

这些内容不应作为“遗漏文件”逐项补拷贝。Avalonia 的目标是保留行为契约，同时采用不同 UI、渲染和平台抽象；但每项仍需有边界和验收证据。

WPF 实现Avalonia 替代判定仍需注意
WPF XAML Window/UserControl、依赖属性和命令绑定Avalonia AXAML、Gekimini docking、CommunityToolkit MVVM、注册式 module/command有意替代同名 View 不代表行为相同；需按用户路径验收。
D3D/OpenGL/CPU WPF render controlsSkia canvas、DrawCommand recording/replay、platform capability有意替代WPF backend 文件不应直接迁移；要核对像素、资源释放和设备失败语义。
WPF Grid/ListView/DataGrid 事件模型Avalonia controls、behaviors、DataGrid、drag/drop manager有意替代/部分键盘、焦点、虚拟化、拖放和多选是行为差异高发点。
NAudio 直接绑定 WPF 生命周期IAudioManager + Desktop NAudio / Browser AudioWorklet有意替代平台 capability、autoplay、设备断开和释放需单独验收。
WPF 文件对话框和 Windows 路径 API平台文件访问抽象、Desktop provider、Browser capability有意替代授权失败、取消、空路径和浏览器沙箱不能套用 Windows 语义。
WPF Visual Studio 脚本编辑联动当前没有等价 Avalonia 脚本执行模块不是替代需先实现脚本/RuntimeAutomation contract，不能将普通文本资源视为替代。

10. 结论与未迁移清单摘要

明确未迁移： EditorScriptExecutor、RuntimeAutomation、领域 MCP（server/tools/resources/skills）、OngekiGamePlayControllerViewer 及 autoplay RPC、OptionGeneratorTools 的 WPF GUI、完整 Save As、Desktop GUI 更新入口/端到端闭环。
部分迁移： PlayableArea 几何算法、Preview SVG 完整视觉等价、拖放和外部文件行为、ProgramUpdater GUI、音频平台能力矩阵。它们已有代码或替代入口，但仍不能声称与 WPF 完全等价。
已迁移主干： Core/Parser/OGKR、palette null 模型、编辑器主路径、属性浏览器、选择和过滤、检查器、谱面列表、转换器、普通保存/自动保存/布局、设置/快捷键、NAudio/Browser 音频基础、DrawCommand/Skia 渲染、主要热路径优化和 CLI 生成/更新命令。

因此，若问题是“master 的改动是否已经整体进入 Avalonia”，答案是没有；若问题是“编辑器主干和当前性能迁移是否已经覆盖”，答案是大部分已覆盖。两者不能混为一个“迁移完成”结论。
