# 节奏曲线（看得见节奏）设计

> 目标工程：`OngekiFumenEditor`（WPF）。Avalonia 树尚未移植（见 `Avalonia/WPF-MIGRATION-SYNC.md` §6）。
> 校验工程：`OngekiFumenEditor.RhythmAnalysisCheck/`（按 csproj 单独调用，不入 sln）。

## 1. 要解决的问题

AudioPlayerToolViewer 原来只有一条振幅包络（`DefaultSamplePeak` → 每毫秒一个峰点）。
振幅包络回答的是「这里有多响」，不回答「这里打了几拍」：底鼓与持续和弦一起抬高包络，
踩镲这类高而短的声音在包络上几乎看不见。

本设计新增一条**频谱域分析链**，把「频谱里突然出现的东西」单独提取出来，
最终只产出**一条 0–1 的节奏强度曲线**，叠加在波形上：

- 持续音与小幅频率变化被压低，起音形成较窄的凸起，而不是铺成能量平台；
- 局部自适应归一化让安静段落的击打更容易看见，绝对尺度下限避免把微小残差抬满；
- 优先保留密集击打和长尾后的弱击打；噪声与衰减尾巴仍可能产生额外凸起，不把曲线等同于准确的鼓点检测。

> 曾经实现过的「鼓点刻度（起音事件着色）」「音频节拍线（BPM 网格）」「面板 BPM 读数」按作者要求
> **已整体移除**（不是默认关闭，是不再存在）：面板上只留节奏曲线。

## 2. 为什么不是直接画频谱图

直接把 STFT 幅度画成热力图（Audacity 那种）并不容易看出节奏：长音、人声、混响会把
瞬态糊住，宽动态范围又让弱拍淹没在强拍旁边。真正决定「看得见节奏」的不是画频谱，
而是**怎么处理频谱**。本实现的每一步都是为了把瞬态从持续内容里剥出来，并让弱拍也看得见：

| 处理 | 目的 |
| --- | --- |
| 对数压缩 `ln(1+300·\|X\|)` | 压缩动态范围，弱拍不被强拍吞掉 |
| 15ms 滞后参考沿频率轴取 ±1 bin 最大值 | 抑制持续谐波的泄漏和小幅颤音，避免宽背景窗口吞掉紧邻的弱击打 |
| `max(0, 当前对数幅度 − 参考 − 0.03)` 后按频段取均值 | 只保留超过固定残差下限的正变化 |
| σ=7.5ms 高斯平滑 + 分频段独立归一化 | 保留密集峰之间的谷；3s 滑窗峰值的尺度下限为 `max(0.1, 原始通量全局 P95×0.25)` |
| 三频段按 1.0 / 1.0 / 0.6 加权合成 | 低频底鼓与中频军鼓撑住重音，高频踩镲保留可见的小包 |

## 3. 算法流水线

`Kernel/Audio/Rhythm/DefaultRhythmAnalyzer.cs`，输入是播放链路已经给出的
`SampleData`（32bit 浮点交错 PCM，目标采样率默认 48kHz），输出 `RhythmEnvelope`。

1. **STFT**：1024 点周期 Hann，跳步 `采样率/200`（5ms/帧，200 帧/秒）。
   帧以窗口中心对齐时间轴，第 `f` 帧代表 `f×5ms`。
2. **对数幅度 + 滞后频谱邻域参考**：`level[f,k] = ln(1 + 300·|X[f,k]|)`；
   `reference[f,k] = max(level[max(0,f−3), k−1..k+1])`，邻域限制在全部非 DC bin 内，允许跨频段边界；
   `rise[f,k] = max(0, level[f,k] − reference[f,k] − 0.03)`。首帧只初始化参考、不计通量。
   生产侧只保存 3 帧已取频率最大值的环形参考谱，无需保存整曲频谱。
3. **频段划分**：按采样率换算 bin 区间——低 20–200Hz、中 200–2000Hz、高 2000–16000Hz；
   每段取 `rise` 的均值得到该帧的谱通量。
4. **平滑与归一化**：每频段先做居中高斯平滑（σ=7.5ms，核半径为 `ceil(3σ/5ms)`，边界按最近样本填充），
   再除以「3 秒滑动最大值」与 `max(0.1, 原始通量全曲 P95×0.25)` 中的较大者，结果截断到 0–1。
5. **合成**：三频段按低 1.0 / 中 1.0 / 高 0.6 加权平均，得到 0–1 的总曲线。

分析侧到此结束；面板再对这条曲线做一次**显示侧色调映射**（`RhythmCurveTone`，见 §5），
映射参数属于观感设置，改它不需要重跑分析。

参数集中在 `DefaultRhythmAnalyzer` 顶部常量区，均已加注释。

当前默认是已验证的**敏感方案**，没有相干能量门控、BPM 依赖或按曲目特判。
旧的 150ms 均值参考与 50ms 均值平滑已从生产分析器移除，仅在独立诊断工程中作为明确的研究对照保留。

## 4. 数据模型

```
RhythmEnvelope(FrameInterval, Total)   // 200fps、值域 0–1 的强度曲线；FrameCount / GetFrameTime 为辅助访问
IRhythmAnalyzer.Analyze(SampleData, CancellationToken) -> RhythmEnvelope
```

- `[Export]` 由 MEF 提供；格式不支持或长度不足时返回 `null`（不画）；分析取消时抛出 `OperationCanceledException`。
- 只依赖 `SampleData`，不碰 UI、不碰 NAudio，可在任意后台线程调用。
- 结果只在分析完成后一次性发布到引用字段，渲染线程只会看到完整结果。

## 5. 渲染

`RhythmGeometry.BuildCurve`（纯函数几何，与 `WaveformGeometry` 同坐标约定）+ `DefaultWaveformDrawing` 中一段绘制：

- **画法**：总曲线按像素列取最大值降采样，关于中轴镜像，随 `WaveformVecticalScale` 竖直缩放；
  顶点数只与视图宽度有关（2×宽度），与歌曲长度、缩放级别无关。
- **显示侧色调映射**（`RhythmCurveTone`，在像素列降采样**之前**、按 200fps 原生分辨率施加，
  所以核宽与缩放级别无关）。**邻域取法**：读取范围向两侧外扩模糊核半径（σ·帧率 ≈ 20 帧），
  落在曲线数据内的部分取真实值，只有超出曲线首尾的部分补 0 —— 既不能拿窗口边缘当信号边缘
  （否则曲线在可视窗口左右两端各有一小段伪影，且随平移移动），也不能拿边界值无限重复
  （否则歌曲末尾的尾音会被压平）：
  1. 局部均值强调 `v' = clamp(v + λ·(v − blurσ(v)), 0, 1)`：σ 固定 100ms（与节拍包宽同量级），
     核用两次盒式滑动均值近似（三角核），不是 O(n·k) 的卷积；曲线本来就平坦时 `v − blurσ(v) ≈ 0`，
     因此**不会凭空造峰**；峰顶被 clamp 在 1，效果体现在把谷压下去、把峰的肩部变陡。
  2. γ 压缩 `v'' = v'^γ`：峰顶保持 1，中低段整体压低。
  两个参数由**强度档位**（`RhythmCurveIntensity`，面板特殊选项里的下拉框）统一给出，
  数值会写进用户设置，**不要改动既有编号**，新增档位往后加：

  | 档位 | γ | λ | 合成用例的峰谷比 |
  | --- | --- | --- | --- |
  | `Default`（色调映射上线前的观感） | 1.0 | 0.0 | 4.00（原样输出） |
  | `Enhanced`（默认档） | 1.5 | 0.7 | 8.67 |
  | `Strong` | 2.0 | 1.3 | 19.52 |
- **默认开启**，可在面板的特殊选项里勾掉（`ShowRhythmCurve`），颜色在音频设置页改（`WaveformRhythmCurveColor`，默认 90, 230, 160）。
- 与离屏图块无关，逐帧实时绘制，因此改颜色/开关立即生效；波形本体的分块预渲染路径不受影响。
- 分析耗时（Release，整曲一次）：274.9s 歌曲 1.2s、242.0s 歌曲 1.1s、216.6s 歌曲 0.9s。

- 特殊选项（`DefaultWaveformOption`，对象检查器里操作）：`ShowRhythmCurve`（勾选框，默认开）、
  `RhythmCurveIntensity`（枚举下拉框，`Default` / `Enhanced` / `Strong`，默认 `Enhanced`）；

独立 holdout 使用 ±40ms 一一匹配和同一可见峰阈值，排除首尾各 0.5s。

| 场景 | 命中 / 已知击打 | 额外可见峰 |
| --- | --- | --- |
| 100 / 190 / 320BPM 鼓组 | 20/20、38/38、61/63 | 5、0、0 |
| 75ms 间隔密集踩镲 | 80/80 | 0 |
| 三种幅度的独立已知击打 | 各 7/7 | 各 0 |
| 恒幅音、恒幅下滑音、纯音高颤音、和弦 + 极小噪声 | 无已知击打 | 各 0 |
| 稳态宽带噪声 | 无已知击打 | 159 |
| 长尾后的弱击打，85 / 155ms 间隔 | 各 6/6 | 20、29 |

## 8. 已知限制

- **曲线是相对变化量**：它不表示绝对能量，安静段与响亮段在数值上被拉平（这是为了看得见节奏），
  因此不能用它判断音量大小。强度档越高曲线越"只有峰没有身"（`Strong` 档能到 19.5:1 的峰谷比），
  需要看清中低段细节时切到 `Default` 档。
- **强调项会放大噪声**：档位越高，撞在一起的镲片之间越容易出现小抖动（平坦段落不受影响）；
  嫌吵就切回 `Default` 档。
- **敏感不等于准确鼓点检测**：强宽带噪声与长尾的随机变化会产生额外凸起；极密集合奏仍可能漏峰。
  这里有意不加相干能量门控，以免再次抹掉弱二次击打，实测取舍见 §7.3。
- **不提供节拍/速度信息**：不再有 BPM 网格与读数，需要速度时只能靠谱面 BPM 与耳朵。
- **高频内容权重较低**：合奏里轻的反拍踩镲在总曲线上只是小包（单频段归一化下才与底鼓等量齐观），
  这是「重音结构优先」的取舍。
- **Avalonia 树未移植**：Avalonia 侧仍只有包络波形；移植点见 `Avalonia/WPF-MIGRATION-SYNC.md` §6。
